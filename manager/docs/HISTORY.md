# Development history

## 1.0.14: a smaller download

- Same code as 1.0.13. The release zip is the Manager exe, its config, README.md and Slotsloader\ (tools\Package-Release.ps1 packs the CLI, CLI.md and VALIDATION.txt only before 1.0.14; VALIDATION.txt now goes beside the zip). Published as a pre-release while 1.0.13 stays Latest, so 1.0.12 and older reach 1.0.13 first.

## 1.0.13: one fighter per click, no CLI in later downloads

- A click on a fighter portrait in Filters now shows only that fighter, so you can go from fighter to fighter quickly; it used to add each one to the filter. Ctrl+click adds a fighter, Shift+click a range, and clicking the selected fighter again clears it.
- The download no longer carries the command-line tool (`Slotsloader CLI.exe`, its config and `CLI.md`) or `VALIDATION.txt`: only the Manager, its config, the README and the bundled Slotsloader. The CLI is still built from the source. The updater accepts releases without them and removes the old copies (kept for rollback). 1.0.13 still ships them so 1.0.12 and older can update to it. Help: rolling back a Manager update is `Slotsloader Manager.exe update-rollback`.

## 1.0.12: installation, options, search and browsing

- An empty Mod library no longer shows a blank list (added to the 1.0.12 download on 23 Oct). With no mod libraries it says to add your mods folder, with a link to Settings → Mod libraries (Add… focused); libraries without mods say so with the same link. The footer names where to add a library.
- Replacement operations reuse each PAK layout hash within one reconciliation. Live file verification, path checks, ownership, journaling and recovery still run. See [measurements and validation](INSTALL-IMPROVEMENTS.md); the measured improvement is from generated fixtures, not an in-game install.
- Root alternatives with the same bundle metadata and complete file destinations now appear in a choose-one group, with no guessed default. Queue installation skips an unresolved choice instead of selecting the first option. Independent components and partial overlays keep their existing behavior.
- Older saved selections containing several equivalent alternatives restore the last effective choice when the composed winning files remain identical, with an explanatory note. Opening a mod does not rewrite its installed record.
- Searching `pak` or `pak mods` finds recorded PAK payloads on Installed and eligible payloads in library archives, including mixed packages. A loose replacement using PAK-entry invalidation is not a PAK payload. Other search terms still narrow the results.
- Fighter portrait filters show confirmed single-character mods first, then multi-character mods, preserving the chosen sort within each group.
- Browsing is instant (the user: options first, the health check later). Opening a mod no longer shows a progress bar or "Reading…" and no longer locks the library list; a pick made during a read replaces the waiting one and stops the read, where it used to be dropped (the list and the inspector could show different mods). Archives read in this session are kept while unchanged, and the next RAR/7Z row is read ahead. The health check starts once browsing settles on a mod (0.9 s), or at once from Install. The footer shows only the result: no stage or percentage text (a 293-file tool mod changed it hundreds of times), and "Checking…" only for a check still running after 1.2 s. The mode notice no longer reads `replace-state.json` for every opened mod (about 50 ms each). Measured on 12 library mods: options show in 60–170 ms instead of 150–860 ms (a 2.2 s 7Z read ahead in 250 ms).

Slotloader Manager was developed privately before its first public release, 1.0.0. These are the internal versions, newest first. They were called SlotsLoader Manager from 2.1.0 to 2.5.8, and SF6 SlotsLoader Installer before that.

  - **PAK-method installs of an external mod manager** (`invalidate`, `pakcopy_reengine_invalidate`) uninstall from the Manager. The game entries it invalidated come back (each one proven, otherwise nothing changes), the mod's patch PAK and the manager's empty placeholders go, and Undo restores it all.   - A restored or undone mod no longer jumps above a mod you installed after removing it.
  - If the copy for Undo can't be saved (a file open in another program), the Manager says so and tries again at the next start.
  - A re-check after a cancelled check continues large RAR/7Z extractions instead of starting over; folder mods are no longer copied again on every check. The "Saved options are missing" footer clears when clicked. A background check can no longer make a change fail by reading at the same instant.
  - Fixed two rare errors: the options list could fail to paint after a mod closed, and the inspector's conflict lines could throw "Collection was modified".

The Installed banner is one slim row: "Loose file loader off: SF6 ignores loose replaced files." with **Turn loose file loader on** and **Use PAK method**. - 2.4.0 (update checks, costume pak clean-up, no tooltips, an Assistant that knows the app):
  - **Update checks**: a few seconds after start (at most once a day) the app asks GitHub whether a newer Slotloader or Slotloader Manager is published. A small panel at the bottom right says so, for example "Slotloader 1.9.9 is available (you have 1.9.8)", with **Update**, **What's new** (the release page), **Skip this version** and **✕** (it comes back at the next check). Nothing is installed without your OK, and every download is checked against the SHA-256 published with the release; a file that doesn't match is deleted.
  - **Update** for Slotloader: shown only when this app installed Slotloader. It downloads and checks the new build, opens it in Replace original and, when the health check has nothing to say, asks once ("Update Slotloader 1.9.8 → 1.9.9?") and updates it in place. The game's genuine amd_ags_x64.dll backup is kept. While SF6 runs it says "Close SF6 to update". Without Slotloader, "click to install it" installs the newest known release (never older than 1.9.7).

  - **The Assistant knows the app**: it answers how-to and troubleshooting questions about the app and Slotloader from this documentation (built into the app), says so when the documentation doesn't cover something, and reads your actual set-up with a new status tool. Notes sit close to their control, results get a clear gap after their button, and multi-line notes have even line spacing. Renamed: the **Installed outfits** tab is **Installed**, the Filters tile **Code tools** is **Tool mods**, **Backups and trash** is **Recover removed outfits**, **Refresh mod libraries** is **Refresh libraries**, and in Settings **Game location** is **Game folder**, **Source libraries** is **Libraries**, **Test connection** is **Test key**, and **Turn loader on** is **Turn loose file loader on**.
