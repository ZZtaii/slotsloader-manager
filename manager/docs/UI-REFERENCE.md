Turn loader on (recommended)." Themed boxes use the main window's text size and are laid out again once their window exists, so they are scaled exactly once. With an external mod manager open, loose/tool actions stay enabled; only PAK-method actions say to close it first (same PAK).) (2.0.4: keyword and character-name starts of three letters or more match in library search; otherwise as 2.0.3) (tool-mod search, library uninstall of replacements, themed message boxes; see the 2.0.3 section below. 2.0.1 added the automatic health check/review, conflict information and costume search; see the 2.0.1 section, which builds on the 2.0.0 Replace original mode, the 1.6.0 Assistant tab and the 1.5.0 polish). This is the standalone personal Windows installer in this project. Its UI work is independent of Blender and RE Mesh Editor.

The 1.3 refresh preserves the established layout. `OptionTree.cs` replaces the native TreeView with a managed, double-buffered hierarchy: complete row backgrounds, indicators and text paint together. Hover only changes the side preview. Keyboard expansion/selection and accessible item actions remain supported. Do not reintroduce native custom-draw suppression as the option-hover fix. The library's separate hover handling remains unchanged.

Current text/layout uses native **PerMonitorV2** DPI from a 96-DPI baseline, including the .NET 4.8 target attribute and matching config. Rows remain 32 logical pixels and text 10.5 points; at 300% rows are 96 physical pixels. The former DPI-unaware/GDI-scaled setup below is historical. Preview decoding also runs on the worker with bounded image dimensions. Progress and Cancel appear during background work; cancellation is disabled during the short install commit.

Installed rows/details show actual Outfit labels from the loader's last `outfits.json`, matched by source path. Manual archives are also visible. New/changed managed outfits display Pending restart; missing/unreadable results are explicit. The gear adds **Backups and trash** for reversible restore and explicit permanent removal. It does not automatically prune anything.

Current implementation and validation details are in [DEVELOPMENT.md](DEVELOPMENT.md). The six October 4 screenshots and measurements below establish the earlier accepted layout, not the current renderer or DPI behavior.

Read this before changing layout, navigation, option selection, previews, or screenshot tooling. The [current usage guide](../README.md) describes the complete user workflow. The 1.2 update added the hover and character-detection work, followed by the 1.2.1 tooltip removal. Its earlier description of rich option tooltips is historical; the follow-up and current source govern the UI.

## User preferences to preserve

- **Give options enough room.** The first design stacked a large preview/header above the list and destination/summary/actions below it. On the user's available screen, only about three option rows remained. This was the problem the redesign needed to solve.
- **Keep the navigation sidebar removed.** Mod library and Installed (called Installed outfits before 2.4.0) are compact top tabs. The gear holds Settings, Open costume folder, and Refresh libraries.
- **Concise text (2.4.0).** The clearest information in the fewest words: lead with what matters, errors give the cause and the next step, one term per concept (extra outfit, Replace original / replacement, tool mod, library, Slotsloader, loose file loader, Manager). Shorter must not mean vaguer.
- **One vertical rhythm (2.4.0, `UiRhythm.cs`).** A control and its own note are close (`Rhythm.Related`, 6), a button and its result get a clear gap (`Rhythm.AfterAction`, 14), groups are further apart (`Rhythm.Group`, 20); multi-line notes use `NoteLabel` (word wrap, line height 1.35, path lines shortened in the middle, height fits the text).
- **Keep options in the tall centre pane.** Preview and destination controls belong in the narrower right inspector; summary and install actions belong in the compact footer.
- **Keep readable rows and text.** Current options use 32-pixel rows and a 10.5-point Segoe UI font. Do not recover space by shrinking this list back to the old small controls.
- **Hover previews are wanted; option popup text is not.** Brief hovering highlights an option and changes its image/details in the side panel. It does not check a box, change precedence, or select a tree row. Version 1.2.1 removed option `TreeNode.ToolTipText` and sets `ShowNodeToolTips=false`. The current review source also removes library-entry hover popups; other control tooltips remain.

## Views and how to reach them

| View | Access | Main purpose |
| --- | --- | --- |
| Mod library — Options | Top **Mod library** tab, open a package, then **Options** | Browse/search/filter source mods; check main files and variant options; inspect hovered previews; name the outfit and choose its character |
| Mod library — Merged files | **Preview merged files**, or the **Merged files** tab | Inspect each winning native file, source component, and size after composition |
| Installed | Top **Installed** tab (Ctrl+2) | Inspect existing outfits; open folders; edit, enable/disable, or uninstall app-managed outfits when eligible |
| Settings | Gear → **Settings…** (Ctrl+,) | Tabs **General** (game folder, 7-Zip, libraries, Assistant), **Game files & replacements** (replacement method, loose file loader, REFramework and Slotsloader, game files, replacement store, external mod manager) and **Updates** |
| Assistant | Top **Assistant** tab (Ctrl+3) | Ask the Assistant to search, inspect and plan installs; approve queued changes in the Plan panel |
| Gear menu | Top-right gear, also available as its context menu | Settings, costume-folder access, and library refresh |
| Composition report | Click the footer's composition summary/details after building a plan | Read required changes, notes, component order, and file overrides in a scrollable modal report |

These cover the custom screens. **Edit options** loads a managed outfit back into the existing Options view; it is not another editor window. Archive/executable pickers and folder browsers are standard Windows dialogs. Since 2.4.1 there are no confirmations for recoverable actions (they act at once with Undo) and errors are inline; the few remaining questions (permanent deletes, another tool's changes) use the themed message box (2.0.3; standard MessageBoxes before). A successful install uses a green checked status line rather than a popup. Taking screenshots does not require installing, disabling, removing, or replacing an outfit.

One chip per filter ("NSFW 158": matches among the mods the other filters leave), then **+ New filter**. States are saved in `view-settings.json` (`FiltersOnly`, `FiltersHidden`, by filter id).
- **Matching**: a keyword matches when its letters and digits (case, accents, spaces and dashes dropped) appear as one run in the file name, the modinfo.ini name, the typed name or any option folder or option name (`LibrarySearch.HasCompact`); one- and two-letter keywords must start a word. While it is open the typed keywords narrow the list (the edited filter's own state is ignored) and the count says "N mods listed". Enter in the name or Ctrl+Enter saves, Esc cancels (the panel stays open), Tab moves between its fields (not INSTALL AS). Picking a mod in the list keeps the panel open while editing; closing the panel cancels. A duplicate name or no keywords is refused in red in the editor. Delete needs no confirmation (the editor is already a deliberate step).
- **Storage**: `Data\library-filters.json` (`slotsloader-library-filters-v1`). Without the file the default **NSFW** filter is listed (so later default keywords reach a user who never edited it); deleting it is remembered. Its keywords come from the user's 2,697-mod library, trimmed by the user (2026-10-20, 153 matches): nsfw, nude, naked, topless, bottomless, pubic, pubes, nipple, pasties, lewd, futa, see through, see thru, no panties, no underwear, erotic. Left out: clothing words (bikini, lingerie, thong, skimpy) and words that hit harmless mods there ("sex" in "passexport", "tless" in "hatless", "transparent" glasses, "r18" in version numbers).

Its content is as tall as the column, or as tall as it needs with the preview at 100 logical px; only then does it scroll. The wheel is taken before the column's controls only when there is something to scroll. Option descriptions wrap in full; REPLACES notes are no longer cut to fit.

This install overrides 16 of them; the other 135 stay active, so the outfit may mix both mods."), from `ReplacePlanner.ConflictParagraphs`; the health report and the Assistant keep the one-line text.
- **REFramework** (the user: flag it like Slotsloader so users know why extra outfits don't load): `ToolStatus` reads the installed `dinput8.dll` (build date, commit, upscaler mark; cached by size and time). The Extra outfit line, REFramework first: "REFramework isn't installed, so extra outfits won't load · click to install it", "Start SF6 once so REFramework can finish setting up; extra outfits load after that" (no click), "REFramework from 1 Jan 2025 is out of date · click to update it" (older than the pinned nightly; never an upscaler build), then Slotsloader's notice. ## 1.0.7 Background library reading, 2026-10-20

Source: `Library.ScanQuick` / `IndexEntry` / `IndexNames` in [Core.cs](../src/Core.cs), [MainFormIndexing.cs](../src/MainFormIndexing.cs). Checks: `--queue-check` "background index".

- **The list first.** A scan (start, F5, ↻) lists every mod with what the index knows (same archive stamp, complete identity) and marks the rest Pending: the row says **Reading…** and, until read, the mod has its file-name fighter only. The window is not busy for the reading.
- **Two background passes**, four mods at a time, rows on screen first: (1) identity from the archive listing (fighter, outfits, option folders, kinds; ZIPs and folders also read their modinfo.ini here), (2) the modinfo.ini names of RAR/7Z archives (display name, option names, authors), which cost a second 7-Zip run. Results are applied every 0.4 s; filters, counts and the Name view follow. The caption reads `N MODS · READING n%`, then `· NAMES n%`. The index is saved every 200 mods and at the end, so a closed window loses nothing already read.
- **Index records**: identity no longer needs the names. A 1.0.5 record (authors, no display or option names) keeps its identity; only its names are read. A full `Library.Scan` (CLI, Assistant) reads missing names inline.
- F5 / ↻ during a run stop it and start a new scan; deletes and renames during a run are safe (a rename keeps the file's content, so the result still applies).
- Fixed: 1.0.6 commented out the refresh of replacements (`ApplyGameRows`), removed-usage and changed-source marks and `UpdateModeUi` after every library scan.

## 1.0.6 Library names, search, queue, Add to outfit, 2026-10-19

Source: [MainFormLibraryView.cs](../src/MainFormLibraryView.cs), [LibrarySearch.cs](../src/LibrarySearch.cs), [MainFormBatch.cs](../src/MainFormBatch.cs), [MainFormAddParts.cs](../src/MainFormAddParts.cs), [InstallerParts.cs](../src/InstallerParts.cs). Checks: `--queue-check` (suite `queue`).

- **Name · File** (under the library search, right): the list shows each mod's own name (its modinfo.ini `name=`; a dummy root's name, else the options' `NameAsBundle=`, else the only top-level option's name) or its archive/folder file name. A mod without a name shows its file name in both. Ctrl+Shift+N flips it. Remembered (`view-settings.json` `LibraryNames`). Ties in every sort follow the shown name. The library index stores the name and every option's name (a 1.0.5 record is listed again once).
- **Search** matches the file name and the mod's name. Several words match one by one, in any order, ignoring spaces, dashes, underscores, case and accents: `viper barefoot`, `barefoot viper` and `cviper` all find `C-Viper-Barefoot-1234-1-0.zip`. A one-letter word must be a whole word and a two-character one the start of a word. A fighter word in a plain search (`juri barefoot`) matches that fighter's mods or names; with commas the fighter is strict as before (`juri, barefoot`, `juri,barefoot`, `juri ,barefoot ,`, `juri;barefoot` are the same search). A costume word works without a comma too: `juri c1` = `juri, c1`.
- **Deep search** (check box beside Name · File, remembered): name words also match a mod's option folders and option names, so `barefoot` finds Goth Juri through its Barefoot variant.
- **Filter changes scroll to the top**, like a search. A refresh, the start-up restore and new fighter portraits don't.
- **Several mods at once.** Ctrl+click, Shift+click, Shift+arrows or Ctrl+A select several rows; the queue replaces the inspector: **INSTALL AS** (Extra outfit · Replace original, the same remembered choice; Tab flips it), one row per mod with its result, **Install N**, **Delete N** and **Close**. Install uses each mod's default options: main files, and for each required choose-one group its "· Default" option, else the first; top-level variants that share files keep the first; optional options stay off. Code tools and PAK mods install as Replace original in either mode. A mod already installed in that mode, Slotsloader itself or a mod with no single fighter (Extra outfit) is skipped with the reason; a failure doesn't stop the rest; Cancel (status bar) stops after the current mod. Extra outfits are named after the mod (" 2" when taken). Delete moves the mods to the Recycle Bin (installed copies stay); the Recycle Bin refusing some asks once for all of them. Space and the lone Ctrl tap do nothing under the queue.
- **Installed → Refresh** (icon left of History, accessible name "Refresh installed") re-reads extra outfits and game-folder mods, like opening the tab.
- **Add to outfit…** (Extra outfit mode; it shares the row under the outfit name with Install all variants, each half the width, one alone takes the row) copies exactly the ticked options' natives files into an extra outfit the Manager installed, instead of a new slot. No main files are needed (one hair option of a bundle is fine), later options win a shared path, and the outfit's files of the same paths are replaced; nothing else is added or removed. The window lists the fighter's outfits with the outfit slot each is built on; an outfit built on another slot than the files' model folders (other than the shared 000) shows the reason and can't be picked, because materials point at their own slot's files. The outfit records what was added (`.slots-installer.json` `Parts`: source, options, files), so Edit options and reinstalls of the same mod copy it back on top; another mod installed under that outfit name starts without it, and the status says what was kept or removed. The same options added again replace their entry.
- **Rename follows Name · File.** With Name on, Rename (F2, right-click) edits only the shown name: it is kept in `Data\library-names.json` by source path (never in the archive or its modinfo.ini), search matches it, a file rename moves it with the mod, a delete forgets it, and an empty name (or the mod's own name) removes it. With File on, Rename renames the archive or folder as in 1.0.5. The edit box gets the row's name font at the screen's DPI (`NativeDpiFont`); before, it kept the 100 % size.
- **No destination line.** The `costume_mods\<fighter>\<outfit>\natives` line under CHARACTER / OUTFIT NAME was removed (the user).
- **Move up / Move down** (Installed, a replacement selected) change the replacement priority: higher in the list wins the files several replacements share. Extra outfits have no order there; Slotsloader numbers them.

## 2.4.3 Slotsloader 1.9.8 pin, detected defaults, 2026-10-15

## DPI and rendering lessons

The user's display used 300% scaling during the original redesign. Before 1.3, `AutoScaleMode.Dpi` was combined with `dpiAware=false`, so Windows scaled a lower-resolution image. That workaround has been removed. Current `app.config`, net48 assembly target and explicit layout scaling provide native DPI; retain all three together.

Distinguish a form's outer size, `ClientSize`, a rendered canvas, and the physical desktop screenshot. The 1232×672 rendered PNG includes the frame; it is not the same measurement as the 1232×640 client-size regression case. The configured form minimum is 1110×650 outer pixels. Tests deliberately clear the minimum to inspect specific client geometries.

Native windows in this environment clamped larger requested geometry to the available desktop. The 1460×920 screenshot/check mode therefore reparents the actual controls into a fixed-size `Panel` canvas. That provides larger-layout coverage while the desktop-sized cases still exercise a native window. A large canvas passing is not a substitute for checking the user's available viewport.

Avoid resize logic that mixes already-scaled measurements with raw font/height assignments. The old stacked layout's height-based shrinking did not create enough usable option space. Keep the option pane's fill layout and stable readable rows; adapt the inspector instead. Inspect long labels, footer text, target fields, top navigation, and Settings actions in the actual smaller viewport.

## Hover and asynchronous preview lessons

`componentTree.MouseMove` hit-tests the row, updates the hover highlight, and starts a **220 ms** timer. Mouse leave stops the timer. `PreviewOption(TreeNode)` shares the same preview path used by row selection. `ShowComponent` updates side-panel metadata, then obtains the image separately from the general `Work<T>`/busy mechanism.

Hover must not set the app busy or disable selection, source browsing, character, or outfit-name controls. Image reads are serialized. While one read is running, the pending request is replaced by the newest one. A generation counter advances on every request, including cached-image requests, so an older result cannot overwrite a newer or cached final choice. Completion also checks the captured package and inspected component. Package changes invalidate generations, clear pending requests, and reset the bounded **64 MB byte cache**. The image placeholder covers loading and unavailable previews; replaced image objects are disposed.

The option tree draws its own check/radio indicators and retains its existing buffered rendering. The extra Options-tree scroll repaint from the earlier review candidate was removed after the user clarified that the missing marks were the mod library's row rails.

For headless checks, install an explicit `WindowsFormsSynchronizationContext` and pump messages. Those entry points run before `Application.Run`; merely watching `previewLoading` was insufficient to prove that a requested image had finished applying. Wait for the intended `previewComponentId`, a usable image, and cleared pending/loading state. The UI now clears the loading flag after applying/cache-processing the completion. Keep both safeguards when changing preview code.
